# Internal Package Creation Rules (`packages/*`)

This document defines the strict standard for creating and maintaining internal packages in this Turborepo. Every internal package must adhere to these specifications.

---

## 1. Directory Anatomy

Every package inside `packages/<name>` must follow this layout:

```text
packages/<name>/
├── src/
│   ├── index.ts          # Main entrypoint or central exports
│   └── ...               # Submodules and implementations
├── package.json          # Package manifest with scoped name and export map
├── tsconfig.json         # Extends @repo/typescript-config
└── README.md             # Brief summary of package purpose and usage
```

For compiled packages only (Archetype C):
```text
├── dist/                 # Generated by build script (gitignored)
```

---

## 2. Package Manifest Templates (`package.json`)

### Template 1: Just-in-Time (JIT) TypeScript Package (Default)
Use this for pure TypeScript modules (`@repo/utils`, `@repo/validation`, `@repo/types`, `@repo/auth-shared`).

```json
{
  "name": "@repo/<name>",
  "version": "0.0.1",
  "private": true,
  "type": "module",
  "main": "./src/index.ts",
  "types": "./src/index.ts",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "default": "./src/index.ts"
    },
    "./*": {
      "types": "./src/*.ts",
      "default": "./src/*.ts"
    }
  },
  "scripts": {
    "check-types": "tsc --noEmit",
    "lint": "eslint ."
  },
  "devDependencies": {
    "@repo/eslint-config": "workspace:*",
    "@repo/typescript-config": "workspace:*",
    "typescript": "7.0.2"
  }
}
```

### Template 2: Universal UI Component Package
Use this for UI and styling primitives (`@repo/ui`, `@repo/theme`).

```json
{
  "name": "@repo/ui",
  "version": "0.0.1",
  "private": true,
  "type": "module",
  "exports": {
    "./button": "./src/button.tsx",
    "./card": "./src/card.tsx",
    "./*": "./src/*.tsx"
  },
  "scripts": {
    "check-types": "tsc --noEmit",
    "lint": "eslint ."
  },
  "peerDependencies": {
    "react": ">=18.0.0",
    "react-dom": ">=18.0.0",
    "react-native": "*"
  },
  "peerDependenciesMeta": {
    "react-native": {
      "optional": true
    },
    "react-dom": {
      "optional": true
    }
  },
  "devDependencies": {
    "@repo/eslint-config": "workspace:*",
    "@repo/typescript-config": "workspace:*",
    "@types/react": "19.2.18",
    "@types/react-dom": "19.2.5",
    "react": "19.2.8",
    "react-dom": "19.2.8",
    "typescript": "7.0.2"
  }
}
```

### Template 3: Compiled Package
Use this only when code must be compiled for runtimes that cannot transpile TS on the fly (e.g., `@repo/db` with Prisma Client).

```json
{
  "name": "@repo/<name>",
  "version": "0.0.1",
  "private": true,
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc",
    "dev": "tsc --watch",
    "check-types": "tsc --noEmit",
    "lint": "eslint ."
  },
  "devDependencies": {
    "@repo/eslint-config": "workspace:*",
    "@repo/typescript-config": "workspace:*",
    "typescript": "7.0.2"
  }
}
```

## 3. TypeScript Configuration (`tsconfig.json`)

Always extend from `@repo/typescript-config`:

```json
{
  "extends": "@repo/typescript-config/base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

For React / React Native UI packages, use:
```json
{
  "extends": "@repo/typescript-config/react-library.json",
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

---

## 4. Forbidden Anti-Patterns

1. **NO TypeScript compiler `paths`**:
   - Do NOT add `"compilerOptions": { "paths": { "@/*": [...] } }` inside internal packages.
   - For internal package imports, use relative paths (`../utils`) or Node.js subpath imports via `"imports": { "#*": "./src/*" }`.
2. **NO Mega-Barrel Files**:
   - Avoid `export * from './everything'` at the root index when the package contains disparate features. Provide granular subpath entrypoints in `"exports"`.
3. **NO Direct React Dependencies in UI Packages**:
   - React must always be a `peerDependency`. Hard `dependencies` cause duplicate React instances, breaking hooks and context providers across apps.
4. **NO Hardcoded Cross-App Imports**:
   - Never import from `../../apps/web` or `../../apps/mobile`. If logic is needed across apps, move it into a package.
5. **NO Redundant `build` Tasks in JIT Packages**:
   - Do NOT declare a `"build"` script in JIT packages that only calls `tsc`. JIT packages do not produce `dist/` and must not waste cache/build cycles in `turbo.json`.

---

## 5. Wiring Into Apps

To consume `@repo/<name>` in an app:
1. In `apps/<app>/package.json`:
   ```json
   "dependencies": {
     "@repo/<name>": "workspace:*"
   }
   ```
2. From the monorepo root, run:
   ```bash
   bun install
   ```
3. In app code, import directly:
   ```typescript
   import { myHelper } from "@repo/<name>";
   // or subpath entrypoint:
   import { specificFeature } from "@repo/<name>/specific";
   ```
4. Verify by running:
   ```bash
   bun run check-types
   bun run lint
   ```
